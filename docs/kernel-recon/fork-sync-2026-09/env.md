**The gap.** Every Wave 1/2 quote from "vanilla 6.18" in this increment is from **6.18.49**, one
stable release short of the 6.18.50 the image builds. Every 7.x quote is from **7.2.3**, one short
of the 7.2.4 the RT variant builds. Records say so in `verification` / `notes`. What a stable
release can do to a disposition is narrow — absorb or move a hunk a carried patch sits on — and
the build (`-F0`) catches the loud half of that on the real 6.18.50 tarball. The silent half is
closed by re-running the drift walk for the missing release once a tree with the tag is reachable:

```bash
# on a machine that can reach kernel.org (or once the gregkh mirror has the tag):
git -C <linux> fetch origin tag v6.18.50 tag v7.2.4
git -C <linux> log --format='%H %s' v6.18.49..v6.18.50 -- $(grep -h '^+++ b/' board/mister/de10nano/linux-patches/*.patch | sed 's|^+++ b/||' | sort -u)
git -C <linux> log --format='%H %s' v7.2.3..v7.2.4 -- $(grep -h '^+++ b/' board/mister/de10nano/linux-patches-beta/*.patch | sed 's|^+++ b/||' | sort -u)
```

An empty result closes the gap; a non-empty one is a handful of rows for the Wave 1 drift-verdict
procedure. `commits.jsonl` `_meta.vanilla_target` must **not** be advanced to `v6.18.50` until
that has been done — set it to the 6.18.49 release commit with a note, or leave it, but do not
claim .50.
